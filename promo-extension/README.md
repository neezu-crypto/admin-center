# SOOP 홍보글·게시판 찾기 (실험용)

관리 센터의 `뻐꾸기/컨텐츠추천/게임 추천 게시판 글쓰기 바로가기 링크 모음` 세션에서 선택한 스트리머의 제목·본문·HTML을 SOOP 게시글 작성 화면으로 전달하고, SOOP 방송국의 게시판 이름을 살펴 홍보 후보 게시판과 글쓰기 주소를 찾는 Chromium Manifest V3 확장 프로그램입니다.

홍보 링크 기본 목록은 관리자 전용 Firebase RTDB에서 제공되며, 공개 확장 프로그램 파일에 기본 목록을 포함하지 않습니다.

## 방송국 게시판 후보 찾기 (0.9.12)

- SOOP 방송국 화면에서 게시판 링크와 메뉴 버튼을 찾아 오른쪽 아래 패널에 후보를 표시합니다. `뻐꾸기`와 `뻐꾹`·`뻐꾺`·`뻐구기` 같은 유사 표기, `게임 추천`·리퀘스트 등 의미가 뚜렷한 이름은 높은 후보, 제안·요청·의견은 확인이 필요한 후보, 단순히 `컨텐츠`/`게임`만 포함된 이름은 수동 확인 항목으로 분류합니다. `게임추천`처럼 띄어쓰기 없는 표기와 `🐟게임 추천🎮`, `게임🎮 추천 게시판`처럼 이모지·다른 문구가 섞인 표기도 인식합니다. `노래 추천` 게시판은 제외합니다.
- 패널은 화면 오른쪽 아래에 고정해 표시합니다. 마우스 위치와 관계없이 같은 자리에 유지됩니다.
- 후보는 높은 후보 → 보통 후보 → 확인 필요 순으로 정렬합니다. SOOP의 메뉴형 게시판은 실제로 링크가 아닌 버튼일 수 있습니다. 이 경우 확장이 버튼명을 후보로 표시하고, `게시판 확인`을 누르면 해당 SOOP 메뉴 버튼을 눌러 이동합니다. `/station/{방송국ID}/board/{게시판ID}` 경로에 도달하면 ID를 읽어 글쓰기 주소 `/station/{방송국ID}/post/write/{게시판ID}`를 구성합니다. 글쓰기 화면이 로드되면 방송국 표시 닉네임과 글쓰기 URL을 줄바꿈으로 연결해 클립보드에 복사합니다. 게시글 작성/게시, 즐겨찾기, 알림 설정은 자동으로 하지 않습니다.
- 패널의 후보 순서대로 `1`–`9`, `0` 키를 누르면 1–10번째 후보 게시판으로 이동합니다. 숫자키로 이동한 게시판 화면에서 `Space`를 누르면 해당 닉네임과 글쓰기 URL을 홍보 리스트에 바로 추가합니다. Space 추가는 숫자키로 이동한 기록이 있고 현재 게시판 ID가 일치할 때만 작동하며, 입력란에 포커스가 있을 때는 단축키가 작동하지 않습니다. 기존 마우스 버튼 동작도 그대로 사용할 수 있습니다.
- 후보 이름은 용도를 증명하지 않습니다. 게시판으로 이동해 작성자와 게시물 성격, 글쓰기 화면에 표시되는 게시판 이름, 실제 작성 권한을 확인하세요. 스트리머 전용/공지/VOD로 보이는 게시판은 제외되지만 SOOP의 권한 상태까지 자동 판별하지는 않습니다.
- 방송국 닉네임은 통합 관리 센터의 실제 전체 홍보 리스트(인증 스트리머와 등록 후보 포함)와 대조합니다. 중복이면 패널에 이미 등록된 닉네임 안내가 표시됩니다. 대조를 위해 네이버 웨일에서 관리자 센터 탭을 열고 관리자 로그인 상태를 유지해야 합니다. 센터 탭이 닫혔거나 목록 조회 권한/네트워크 문제가 있으면 미등록이라고 단정하지 않고 확인 불가로 표시합니다.
- 웨일 확장프로그램 단축키 `Alt+Shift+U`를 누르면 현재 SOOP 페이지에서 프로필 상태 아이콘이 `？`인 다음 스트리머의 방송국을 새 탭으로 엽니다. 현재 검색 탭은 유지되며, 반복해서 누르면 검색 결과에서 다음 미확인 스트리머를 새 탭으로 엽니다. 일반 본문이나 다른 UI의 물음표 문자는 검색하지 않습니다. 웨일 확장프로그램 단축키 설정 화면에서 키 조합을 변경할 수 있습니다.
- 단축키 진단은 확장 프로그램의 서비스 워커 콘솔에 `[SOOP 홍보 단축키 진단]`으로 기록됩니다. `browser-command-fired`는 웨일이 확장 명령을 전달한 시점, `browser-command-received`는 SOOP 탭에 전달된 시점, `shortcut-station-open-requested`는 새 탭 열기 요청, `shortcut-station-tab-created`는 새 탭 생성 완료, `shortcut-candidate-found` 또는 `shortcut-no-candidate`는 페이지 탐색 결과입니다. `listener-ready`만 보이고 `browser-command-fired`가 없으면 웨일의 확장프로그램 단축키 설정에서 해당 키 조합이 지정됐는지 확인하세요.
- SOOP 통합검색·VOD·카테고리 등의 방송국 프로필 이미지가 로드되면 표시 닉네임과 방송국 ID를 통합관리센터의 전체 홍보 목록에서 조회해 이미지 옆에 `✅`(등록됨), `🚫`(제외됨), `？`(미등록/확인 중/확인 불가) 아이콘으로 표시합니다. 같은 닉네임의 조회 결과는 30초 동안 캐시합니다. 마우스 호버 UI는 없으며, 프로필 이미지 클릭의 기본 방송국 이동 동작은 유지됩니다.
- 게시글 댓글의 작성자 프로필 아바타도 등록 상태를 표시합니다. 댓글 아바타는 버튼형 프로필과 이미지의 SOOP 아이디를 읽으며, 상태 확인만 가능하고 제외/해제 동작은 하지 않습니다.
- `？` 아이콘을 눌러 미등록 스트리머를 제외 목록에 추가하고, `🚫` 아이콘을 눌러 제외를 해제할 수 있습니다. 상태는 통합관리센터의 게시판 후보 패널에도 반영됩니다. 제외·해제는 관리자 센터 로그인과 callable 배포가 필요합니다.
- 이미 홍보 리스트에 등록된 닉네임이면 중복 안내만 남기고 후보·설명·버튼은 숨깁니다.
- 글쓰기 화면 로드 시 자동 복사가 성공하면 알림에 `홍보 리스트에 추가` 버튼이 표시됩니다. 누르면 관리자 센터의 인증된 서버 기능이 닉네임·SOOP ID·실제 글쓰기 URL을 확인해 홍보 후보로 등록하고, 관리자 센터 목록을 새로고침합니다. 관리자 센터를 열고 로그인한 상태여야 하며, 기존 홍보 명단과 중복되면 추가하지 않습니다.
- 메뉴 후보를 눌러 실제 `/station/{방송국ID}/board/{게시판ID}` 화면에 도달하면 해당 게시판의 글쓰기 URL이 확정된 것으로 보고, 그 게시판 행의 패널에도 `홍보 리스트에 추가` 버튼을 표시합니다. 추가 시 현재 게시판 ID와 글쓰기 URL의 방송국/게시판 ID를 대조합니다.
- SOOP의 SPA 화면 전환 중 확장 메시지에 이전 게시판 URL이 남을 수 있어, 후보 등록은 현재 글쓰기 페이지 주소와 클립보드용 URL이 일치하는지 함께 확인합니다.
- 탐색은 현재 페이지 DOM의 링크와 버튼을 읽는 방식입니다. 사이드바가 접혀 있거나 게시판 항목이 아직 로드되지 않았으면 빈 상태를 표시하고 DOM 변화 및 SPA 경로 변화를 따라 재검사합니다. 페이지 구조가 달라 항목을 읽지 못하면 추측으로 주소를 만들지 않습니다.
- 후보는 로컬 패널에만 표시하며 통합 관리센터 서버나 외부로 전송하지 않습니다.

### 진단 로그

방송국 페이지 개발자 도구 Console에서 `[SOOP 홍보 게시판 진단]`을 검색하세요. `scanner-initialized`, `station-route-detected`, `promo-duplicate-lookup-requested`/`promo-duplicate-lookup-succeeded`/`promo-duplicate-lookup-failed`, `no-board-navigation-items-found`, `board-scan-complete`, `board-classified`, `board-button-classified`, `board-button-open-requested`, `current-board-route-detected`, `write-page-clipboard-armed`, `write-page-route-detected`, `write-page-clipboard-succeeded`/`write-page-clipboard-failed`, `scan-failed` 로그에 스캔 ID·방송국/게시판 ID·분류 이유·링크/버튼 개수·복사 단계 결과가 남습니다. 게시글 본문·쿠키·인증 토큰은 기록하지 않습니다. 오류를 공유할 때는 해당 접두사의 로그만 복사하고 브라우저의 토큰/쿠키는 공유하지 마세요.

현재 자동 분류는 이름 기반 1차 후보 추출이며 실제 SOOP 화면에서의 실사용 검증은 별도입니다. 특히 지역·계정별 DOM 차이, 비공개/팬 전용 접근 권한, SOOP URL 구조 변경은 시험이 더 필요합니다. 이 단계에서는 글쓰기 링크를 실제로 열어 재확인하도록 하고, 자동으로 홍보 리스트에 등록하거나 게시 완료로 처리하지 않습니다.

## 현재 범위

- 관리자 센터 홍보 목록의 `글쓰기 열기`를 누르면 해당 스트리머의 홍보글을 생성해 SOOP 글쓰기 화면에 전달합니다.
- `홍보글 생성` 패널에서 내용을 확인·수정한 뒤 패널 안의 `글쓰기 열기`를 눌러도 작동합니다.
- SOOP 글쓰기 페이지의 제목과 본문 편집 영역에 생성된 내용을 입력합니다.
- 본문은 SOOP 편집기의 붙여넣기/입력 이벤트로 전달합니다. 화면 DOM만 직접 바꾸는 방식은 사용하지 않으며, 입력 결과가 글자처럼 보이거나 편집기에서 비어 있다고 판단되면 성공으로 표시하지 않습니다.
- 기존 단건 `글쓰기 열기`는 계속 수동 게시 방식입니다. 별도의 `순차 자동 게시`에서 자동 게시를 명시적으로 시작하면, 미완료·유효 링크 항목을 최대 10건까지 하나씩 엽니다. SOOP 편집기 입력과 제목·본문·이미지·게임 링크를 확인한 뒤 5초 중단 대기 후 게시 버튼이 정확히 하나일 때만 클릭합니다. 자동 게시가 필요 없으면 테스트(입력만) 모드를 사용하세요. 이 모드는 게시하지 않고 완료 표시도 바꾸지 않습니다.
- 배치 게시의 대기시간은 게시 완료 확인 뒤 30초~10분, 반복 수는 1~10건으로 제한합니다. 게시글이 실제 등록되어 SOOP 주소가 `/station/{방송국}/post/write/{게시판}`에서 `/station/{방송국}/post/{게시글}`로 바뀌고, 제목과 게임 링크가 작성 내용과 일치할 때만 관리 센터에 홍보 완료를 표시합니다. 게시글 제목과 링크 주소가 상세 화면에 연속 확인된 뒤 완료 처리하며, 링크 텍스트 대신 실제 `href`도 비교합니다. 화면 전환 직후의 일시적인 불일치는 경고 로그로 남기지 않고, 10초 이상 계속될 때만 오류 안내를 표시합니다. 본문 첫 문장을 수정해도 게임 링크가 남아 있으면 확인할 수 있으며, 게시글이 새 탭에서 열려도 같은 방송국과 글 내용으로 작성 건을 찾아 처리합니다.
- `Esc` 또는 관리 센터의 `중단` 버튼은 다음 사이클을 막고, 아직 게시 버튼을 누르지 않았다면 현재 게시도 취소합니다. 게시 요청이 이미 전송된 경우에는 그 요청을 되돌릴 수 없으며, 결과 확인 뒤 다음 사이클만 중단합니다. 제목·본문 불일치, 게시 버튼 부재/중복, 게시 상세 화면 이동 실패, 실제 게시 확인 시간 초과 시에는 자동으로 다음 대상을 건너뛰지 않고 전체 배치를 멈춥니다.
- SOOP `게시` 버튼 클릭을 기록하고, 게시 후 상세 화면으로 이동하는 초기 20초 동안 확인 주기를 250ms로 단축합니다. 제목과 본문 링크가 500ms 이상 같은 게시글에서 유지되는지 확인한 뒤 완료 처리합니다. 새로고침이나 전체 페이지 이동이 발생해도 같은 탭의 세션 상태를 이용해 빠른 확인을 이어가며, SOOP의 SPA 화면 전환에서 확장 메시지의 이전 URL이 남는 경우를 피하도록 현재 페이지 URL을 함께 검증합니다.
- 게시 버튼 클릭만으로 완료 처리하지 않습니다. 게시 화면 전환이나 제목·본문 확인이 실패하면 자동 체크하지 않으며, 관리 센터 탭을 닫았거나 로그인 세션이 만료된 경우도 저장되지 않을 수 있습니다.
- 작성용 내용은 확장 프로그램 로컬 저장소에 탭별로 잠시 보관하고, 해당 SOOP 탭에서 한 번 가져온 뒤 삭제합니다. 게시 완료 추적 정보는 확장 프로그램을 새로고침해도 유지되며, 게시 확인 또는 2시간 만료/브라우저 재시작 시 정리됩니다.
- 접근 권한은 관리자 센터와 SOOP 방송국 URL에 한정되며, 클립보드 자동 복사를 위해 `clipboardWrite` 권한을 사용합니다.

## 설치 및 시험

아직 확장 프로그램 저장소에 등록된 제품이 아닙니다. 웨일의 확장 프로그램 관리 화면에서 개발자 모드를 켜고 이 폴더를 압축해제된 확장 프로그램으로 불러와야 합니다. 외부 소스의 확장 프로그램을 로드하기 전에는 manifest의 권한과 대상 URL을 확인하세요.

첫 시험은 관리 센터의 `테스트(입력만, 게시 안 함)`를 켜고 반복을 1건으로 실행합니다. 제목·본문·이미지와 게임 링크가 SOOP 작성란에 들어오는지만 확인하며 게시나 완료 표시는 하지 않습니다.

코드가 갱신되면 `whale://extensions`에서 개발자 모드의 새로고침 버튼을 눌러 확장 프로그램을 다시 불러온 뒤, 관리자 센터 탭도 새로고침합니다. 실제 게시를 실행할 때는 확인 대화상자에 표시된 대상 목록을 살펴보고 시작하세요. 각 대상은 게시 직전에 5초 대기하며 `Esc`로 멈출 수 있습니다.

## 자동 완료 진단

버전 0.6.0부터 홍보 완료 흐름의 진단 로그를 단계별로 출력합니다. 0.6.1부터 `publish-button-click-detected`, `post-fast-watch-started` 로그로 게시 클릭과 빠른 확인 시작 여부도 표시합니다. 0.6.2부터 SPA 주소 판정 실패 로그에 `senderPath`, `tabPath`, `reportedPagePath`가 포함됩니다. 0.9.37부터 `promo-batch-started`, `promo-batch-state-updated`, `auto-publish-button-clicked`, `promo-batch-item-confirmed`, `promo-batch-stop-requested` 등으로 순차 자동화 단계를 기록합니다. 본문 원문은 기록하지 않고 진단 ID, 배치 진행 상태, 탭/게시글 식별 정보, 제목·게임 링크 일치 여부, 저장 성공/실패 사유만 기록합니다. 브라우저 콘솔에서 `[SOOP 홍보 진단]`을 검색하면 됩니다.

실패를 재현할 때는 확장 프로그램 업데이트 후 `whale://extensions`에서 확장 프로그램을 새로고침하고, 통합 관리 센터도 새로고침한 다음 `글쓰기 열기`부터 한 건만 진행하세요. 게시 후 체크되지 않으면 아래 세 곳에서 같은 진단 ID의 로그를 확인합니다.

1. SOOP 게시글 상세 탭의 개발자 도구 Console — `draft-received`, `editor-fill-verified`, `post-detail-watcher-started`, `post-confirmation-result` 단계
2. `whale://extensions`의 확장 프로그램 상세 화면에서 `서비스 워커` 검사(Inspect) — `pending-created`, `published-post-content-checked`, `admin-completion-request-sent`, `completion-flow-succeeded` 단계
3. 통합 관리 센터 탭의 개발자 도구 Console — `admin-bridge-received-completion`, `firebase-callable-started`, `firebase-callable-succeeded` 또는 `firebase-callable-failed` 단계

## 스트리머 인증 쪽지 자동 확인 (0.9.31)

- 자매 게임에서 스트리머 인증을 신청하면 조건에 따라 6자리 확인 코드가 표시됩니다. 코드를 눌러 복사한 뒤 `SOOP 쪽지 보내기`를 눌러 관리자(`skftodwocks2`)에게 쪽지 본문으로 보내세요. 계정 전환은 발신 SOOP 아이디가 기존 인증 스트리머의 SOOP 아이디와 정확히 같을 때만 자동 승인됩니다.
- 통합 관리 센터에서 `인증 스트리머 관리` 화면을 열어 둔 상태로 SOOP 받은 쪽지함 탭도 열어 두면, 코드가 유효한 신규 인증·계정 전환 신청을 확인합니다. 일치하는 신청이 있을 때만 쪽지함을 최대 10초 간격으로 새로고침하고, 쪽지 목록에 표시된 발신자 SOOP 아이디와 6자리 코드가 검증 조건과 맞으면 기존 인증 승인 또는 계정 전환 승인 처리를 실행합니다. 기존 계정 ID가 없거나 식별 정보가 모호한 요청은 수동 검수로 남습니다. 받은 쪽지 상세 화면은 열지 않으므로 미확인 쪽지를 읽음 처리하지 않습니다.
- 자동 확인은 코드 발급 후 15분까지이며, 확장 프로그램이 열린 받은 쪽지함과 로그인된 관리자 센터 탭이 필요합니다. 코드는 한 번만 승인에 사용할 수 있습니다. 신청이 만료됐으면 게임의 `승인됐는지 확인하기`를 눌러 새 코드를 받으세요.
- 자동화가 실패하거나 쪽지 발신 ID가 기존 인증 계정과 다르면 기존 관리 센터의 수동 승인/거절 버튼을 사용할 수 있습니다.
- 진단은 받은 쪽지함 콘솔의 `[SOOP 스트리머 인증 쪽지]` 및 관리자 센터 콘솔을 확인하세요. 진단에는 쪽지 본문이나 확인 코드가 기록되지 않습니다.
- SOOP 받은 쪽지함의 중첩된 링크/셀 구조에 대응해, 발신자 아이디와 코드가 함께 포함된 가장 가까운 행 텍스트를 최대 24단계 위쪽까지 찾아 읽습니다. 일치 후보가 없을 때는 `inbox-scan-complete` 로그의 `candidatesNotParsed`에 본문이나 코드 없이 판정 실패 유형과 탐색 깊이별 개수만 기록하고, 중복 방지로 건너뛴 후보 수는 `alreadySeen`에 표시합니다.
- 인증되지 않은 후보는 완료 처리로 영구 저장하지 않고 30초 간격으로 다시 확인합니다. 이전 버전이 남긴 실패 후보 기록도 제거하며, 재시도 제한에는 쪽지 번호와 발신자 ID만 저장하고 인증 코드는 저장하지 않습니다.
- 확장 프로그램을 갱신해 기존 관리 센터 콘텐츠 스크립트의 런타임 컨텍스트가 무효화된 경우, `Extension context invalidated` 예외를 내는 대신 안전하게 무시하고 콘솔에 `verification-inbox-watch-skipped-context-unavailable`을 기록합니다. 갱신 후에는 관리 센터 탭을 새로고침해야 새 콘텐츠 스크립트가 연결됩니다.

## 온이유 이용권 후원 자동 확인 (0.9.36)

- 신청자는 온이유에서 본인의 SOOP 닉네임·아이디를 입력해 신청한 뒤, 열린 SOOP 탭에서 운영자 방송국에 별풍선 50개를 후원하고 온이유 화면으로 돌아와 `후원 완료 · 자동 확인 시작`을 눌러야 합니다.
- 관리 센터에 관리자로 로그인하면 제한된 확장프로그램 세션을 발급하고, 확장프로그램 백그라운드가 Cloud Functions의 RTDB `onValue` 스트림을 구독합니다. 주기적인 신청 목록 조회는 하지 않습니다. 브라우저가 백그라운드 작업자를 중단하면 30초 알람으로 스트림을 다시 연결하며, 연결 직후 `onValue` 초기 스냅샷으로 놓친 상태를 보충합니다. 관리 센터 화면의 신청 목록도 같은 실시간 스트림으로 갱신됩니다.
- 확장프로그램 콘솔에 `onyu-gift-background-feed-connected`가 표시되거나 관리 센터에 `백그라운드 실시간 구독 연결됨`이 보이면 관리 센터 탭을 닫아도 됩니다. 새 브라우저 세션 또는 확장프로그램 업데이트/새로고침 뒤에는 `chrome.storage.session`의 인증 정보가 초기화되므로, 관리 센터에 다시 로그인해 백그라운드 세션을 시작해야 합니다.
- 후원 완료 신호가 있는 신청이 있을 때에만 확장 프로그램이 로그인된 SOOP 탭의 알림 종을 최대 10초 간격으로 열어 알림 목록을 확인합니다. 서버 구독만으로 SOOP 알림 DOM을 읽을 수는 없으므로, 자동 확인이 끝날 때까지 SOOP 로그인 탭은 열어 두세요. 브라우저가 종료된 동안에는 동작하지 않습니다.
- 확장 프로그램은 알림 목록의 프로필 방송국 링크에서 발신 SOOP 아이디, 알림 내용의 별풍선 수량, 시각 정보를 읽습니다. 개별 알림을 누르지 않으며 읽음 처리·전체 페이지 새로고침·SOOP 비밀번호 입력을 하지 않습니다. 로그인 정보, 쿠키, 알림 전체 본문은 서버에 보내지 않습니다.
- 서버는 후원자 ID·별풍선 50개·후원 완료 시각과 대기 신청을 대조합니다. 신청이 하나로 특정되지 않거나 상대 시각이 신청 시간 범위와 겹치지 않으면 자동 승인하지 않고 관리자 수동 검수에 남깁니다. 한 SOOP 스트리머에 대한 중복 선물은 서버 트랜잭션 잠금으로 막고, 거절되면 잠금을 해제합니다.
- 자동 승인 또는 수동 처리 결과는 신청자 온이유 화면에서 10초 간격으로 조회해 표시합니다. 자동 확인이 끝나지 않으면 관리 센터의 수동 승인/거절 기능을 사용할 수 있습니다.
- 확장 프로그램은 별도 스토어 배포가 아니므로 코드 변경 후 `whale://extensions`에서 이 압축해제 확장 프로그램을 새로고침한 뒤, 통합 관리 센터에 한 번 로그인해 백그라운드 실시간 구독 연결을 확인하세요. 연결이 확인된 뒤에는 관리 센터 탭을 닫아도 됩니다.
- 진단은 SOOP 탭의 `[SOOP 온이유 이용권 자동 확인]`, 관리 센터의 `[온이유 이용권 자동 확인]` 및 `[SOOP 홍보 진단]` 로그를 확인하세요. 인증 정보나 알림 원문은 진단 로그에 포함하지 않습니다.
- 백그라운드 세션은 Firebase `signInWithCustomToken` 응답에 UID 필드(`localId`)가 없을 수 있으므로, 응답의 ID 토큰에 포함된 Firebase 사용자 ID를 사용해 검증합니다. 이 처리 수정 후에는 `whale://extensions`에서 확장 프로그램을 새로고침하고 관리자 센터 탭도 새로고침해야 합니다.
- 모니터 권한 클레임은 커스텀 토큰에도 명시해 새 세션의 ID 토큰에 포함시키며, 확장프로그램은 피드 연결 전에 UID와 모니터 권한 클레임을 확인합니다.
- 피드 연결이 거부되면 서비스 워커 로그에 `origin-not-allowed`, `id-token-invalid`, `monitor-session-invalid` 등 안전한 실패 사유를 표시합니다. 서버 로그에는 토큰이나 사용자 UID를 남기지 않고 검증 단계와 오류 코드만 기록합니다.

진단 ID가 연결되지 않거나 단계 중간이 비어 있으면 해당 직전 단계에서 끊긴 것입니다. 로그를 공유할 때는 `[SOOP 홍보 진단]` 행만 복사하면 되며, 브라우저의 다른 로그나 쿠키·토큰은 공유하지 마세요.
